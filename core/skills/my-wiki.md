# my-wiki — the brain, projected as a page a person reads

Obsidian shows every file of the brain in the order of the folders, machinery included. This skill
shows the same brain the way its owner thinks about it: entities on their shelves, the initiatives
under the entity they are about, the people, one search box — and, first of all, Overview: what is
waiting for a person right now.

**Nothing is written twice.** The page is a projection: it reads the files and git, and writes
nothing back. What it shows is wrong only when the brain is wrong.

## How it is run

```
.os/core/lib/my-wiki.sh --brain .
.os/core/lib/my-wiki.sh --brain . --out /tmp/my-wiki.html
.os/core/lib/my-wiki.sh --brain . --days 7 --week 14
```

`--out` names the destination file; with none, it goes to `$TMPDIR`. **A destination inside the
brain is refused**: the page is derived and disposable, and a generated file left inside the brain
would show up as work in every scan from then on. `--days` is the window of Overview's threads
(default 3) and `--week` the window of its dated tasks (default 7).

It prints the path it wrote, the size, and how many pages and workspaces the page carries.

## What the page shows

- **Overview, the first screen.** The Claude Code threads of the last days whose last turn is the
  agent's — grouped by the focus each session named — the specs waiting for a Gate 1 and the
  branches waiting for a merge, the `waiting_on:` that is somebody else, and the tasks with a date
  inside the week. **Claude Code keeps no record of what a person opened**: a thread that finished
  without asking anything is shown as *finished · unread*, and the page says on screen that it is
  showing it for lack of that datum, never as a fact. A machine with no local sessions says so and
  shows the other three blocks.
- **A workspace selector**, one page for every workspace of the brain. The root is never shown:
  what lives there is machinery, and the machinery is not the person's work.
- **A shelf per entity type the tree declares** — whatever they are called in this brain. No type
  is written into the skill: a brain that declares `patients/` gets a Patients shelf, and a brain
  with no entity type at all gets its workspace with a notice and no invented shelves.
- **An initiative hangs from the entity its `about:` names.** One that declares none is listed
  under *No entity* — visible, never hidden.
- **The sections of a page are the `##` of its file**, each with its shape: tasks when the lines
  carry checkboxes, decisions when they start with a date, people when they point at `people/`,
  and rendered prose for everything else.
- **Development**, only on a node with `repo:`: the specs by state and the last merge, read from
  the local path `mounts.md` declares for that remote. A repo this machine has not mounted says so
  and nothing fails.
- **What changed**, from `git log` over the window, grouped by entity and initiative.
- **Graph**, one screen more of the page (spec 061, its canvas rebuilt by spec 066 to the vara of
  Obsidian): every page as a node on a `<canvas>` with its own physics — nodes settle by force,
  drag one and it stays where it is dropped, the background pans, the wheel zooms centred on the
  cursor, a double-click fits the whole graph. An edge for every `about:`, every path to another
  page inside backticks and every path into `people/` — nothing else. Hover highlights a node's
  neighbours and opens its page on click, *Show documents*/*Show people* filter a type without
  recomputing the rest, and *How it grew* steps the graph through the first-commit date of every
  page. No library loads from outside the page.
- **Search**, inside the page, over titles and bodies of the workspace being read.
- **Appearance** — accent, type, size, theme — changed from the page and remembered by the browser.

*Edit markdown* opens the note in Obsidian (`obsidian://open?vault=…&file=…`) and copies the path
to the clipboard at the same time: a published page runs in a sandbox that may refuse the scheme,
and the path is what the person needs either way.

## Publishing it

**The script never publishes.** The session does, with the **Artifact** tool, and the person
approves that turn:

1. Run the script and read the path it printed.
2. Publish that file with the Artifact tool, passing its path: title **My Wiki**, and the
   comments capability, so the page can be commented on. The page carries its own favicon-less
   head; the tool asks for one on a first publish.
3. Hand the person the URL, and say the page is private until they share it.

**A second run publishes to the same URL**, not to a new one: the same file path this session, or
the artifact's URL from a later session. A new URL every time turns the wiki into a pile of stale
copies.

**Publishing puts the content of the brain on claude.ai** — private by default, and off the
machine anyway. It is offered, never done on its own.

## Reading the comments afterwards

A comment on the published page is how the person sends something back: a correction, a task to
move, a document to rewrite. To read them, the session calls the Artifact tool with the page's URL
and the `comments` action; a thread the person sent to Claude is the one that can be replied to and
resolved.

**A comment is a request, not an edit.** What it asks for is applied to the file in the brain, in
the session, the way any other change is — and the page is regenerated and republished afterwards.

## What it does not do

It does not edit the brain, does not capture, does not mark a task done, and does not open a
thread of its own. It does not show the archive of a node, and it does not embed images or
attachments: it links to them.
